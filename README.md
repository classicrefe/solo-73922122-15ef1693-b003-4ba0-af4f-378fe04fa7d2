# 赔款发展三角 · 月结网页

精算月结工具：Flask + SQLite。按月导入赔款 CSV、逐月封账、按（事故月 × 支付月）
净变动归档汇总，并可按任一已结月回查当时的累计赔付发展三角。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在名为 `closing-data` 的卷中（容器内 `/data/closing.db`）。
删除数据重来：`docker compose down -v`。

## 网页演示流程（重报 / 改回 / 零抵消 / 两期回查）

仓库自带演示数据：`demo/claims_2026-01_base.csv`（基础批）、
`claims_2026-02_supplement.csv`（补报 + 更正）、`claims_2026-03_revise.csv`
（重报）、`claims_2026-03_revert.csv`（改回）、`claims_2026-04_after_zero.csv`
（零抵消后的下期更正）。

1. **设置首个待结月**：首页 →「待结月设置」→ 填 `2026-01`。
2. **导入基础批**：`claims_2026-01_base.csv` → 7 笔计入 2026-01 期。
3. **封账 2026-01**：7 个组合；封账成功后本期副本全部释放，待结月到 2026-02。
4. **导入补报/更正批**：`claims_2026-02_supplement.csv`（7 笔，其中 3 笔同号覆盖：
   C-0002 改金额 80000→95000；C-0004 改支付月 2026-01→2026-02；C-0007 同数重报）。
   此时封账页「额外留存的逐笔副本」显示 **2**（只有 C-0002、C-0004 与上次封账不同；
   同数重报与未封过的新赔款都不占副本）。
5. **封账 2026-02**：仅归档 6 个净变动组合，封账后副本归零，待结月到 2026-03。
6. **导入重报批**：`claims_2026-03_revise.csv`（5 笔与上次封账不同：C-0002、C-0003、
   C-0004、C-0005、C-0008）→ 封账页副本数 **5**，预览净变动 +5,000 / +25,000 / +30,000。
7. **导入改回批**：`claims_2026-03_revert.csv`（C-0002、C-0003、C-0005 改回上次封账值，
   C-0007 同数重报）→ 副本数降为 **2**（只剩 C-0004、C-0008 这两笔零抵消更正）。
8. **封账 2026-03**：三笔改回互相抵消，本期净变动为 0、归档 0 个组合，副本释放。
9. **导入下期更正**：`claims_2026-04_after_zero.csv`（只改 C-0004 55000→52000）→
   封账页副本 **1**。封账 2026-04 后归档 −3,000：上期零抵消不影响逐笔金额基线，
   下期按 2026-03 封账时的逐笔金额（55000）扣减。
10. **两期回查**：「三角回查」起始事故月 `2025-10`，已结月可选 `2026-01` … `2026-04`，
    历期口径均按当时归档重建，不受后续改回影响。

也可以脚本化演示（服务已启动时）：

```bash
bash scripts/demo_curl.sh http://127.0.0.1:8000
```

## CSV 格式

表头四列（顺序不限，支持 `赔款号/事故月/支付月/金额` 等别名）：

```csv
claim_no,accident_month,payment_month,amount_cents
C-0001,2025-10,2025-10,120000
```

- `claim_no`：赔款号，每批内唯一；与历史批次同号则**整笔覆盖**（可改事故月、支付月、金额）。
- `accident_month` / `payment_month`：`YYYY-MM`；支付月须在事故月至当前待结月之间（含首尾）。
- `amount_cents`：非负整数，单位分。
- 任一行非法 → 整批拒绝，不留部分结果。

## 设计要点

- **期间归属**：每批记录导入时的待结月为所属期间；封账时只归档本期批次的净变动。
  导入与封账重叠时，进程内写锁 + SQLite `BEGIN IMMEDIATE` 单事务保证整批按提交
  先后计入本期或下期，失败整体回滚。
- **增量归档**：`archive` 只保存每期净变动非零的（事故月 × 支付月）组合；封账时对
  本期批次触及的赔案做「当前值 − 上次封账值」差分。补报和更正因此从下一次封账起可见。
- **逐笔副本按需留存**：`claim_archived` 不再为每笔已结赔款永久保留快照，只保存
  「上次封账值」这一份基线，且**只给发生变化**的赔款留：
  - 与上次封账相比事故月 / 支付月 / 金额有变化 → 留 1 份（每笔至多一份）；
  - 同号反复重报 → 始终保留最初封账值，最终值按最后一次导入计；
  - 最终值改回上次封账值 → 立即释放副本，本期不产生变动；
  - 未封过的新赔款没有基线 → 不占副本，封账时按全额计入本期变动；
  - 已结且本期未触及 / 同数重报的赔款 → 无副本，当前值即基线；
  - 成功封账 → 释放本期副本；导入或封账失败 → 事务回滚，副本保持原状。
  `claims.ever_closed` 标记已结赔款，用来区分「新赔款」与「封过但本期未变」。
- **零抵消**：几笔更正即使同组合合计为零，下期仍按本次封账时的逐笔金额与月份扣减；
  零额组合不写归档行，但基线照样推进。
- **只读回查**：三角回查只读 `archive` 汇总（`close_month ≤ 所选已结月` 求和后逐月
  累计），已结三角不受后续补报/更正影响。列范围到最新已结月，封账月之后留空，
  事故月之前显示「—」，已到月份零额显示 0。
- **封账约束**：只能封当前待结月，成功后自动进入次月；有数据后首个待结月不可再改。
- **封账页**显示「当前额外留存的逐笔副本」数，便于核对只留变化项是否生效。

## 旧库升级

旧版为每笔已结赔款都保留一份快照。首次用新版启动时在一个事务内自动升级：

- `claims` 增加 `ever_closed`，标记已有快照的赔款为已结；
- 删除「快照 == 当前值」的副本（已结未变动，不再需要），保留「快照 != 当前值」
  的副本——也就是已有的待结更正，下一期封账仍会按原逻辑扣减；
- 不触碰 `archive`，历期三角沿用原归档，回查口径不变。

升级失败（例如数据库只读、被锁或磁盘错误）时整体回滚，库保持旧结构，应用照常
启动并按旧版逐笔快照逻辑封账；封账页会提示当前处于旧结构。修好问题后重启即可重试。

## 已知限制

- 使用 Flask 内置服务器（单进程多线程），面向内部演示/小团队；生产化可换
  gunicorn（须保持单 worker 以维持进程内写锁，或改用数据库级互斥）。
- 无登录鉴权；金额上限 15 位整数分；时间戳为 UTC。
